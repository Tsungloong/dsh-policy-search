# 部署与操作

## 使用条件

- 插件 0.1.1 要求 DSH 0.2.1-rc.2；本次在 Windows Node 24.14.0 验证。旧 DSH 0.2.0-rc.2 对应插件 0.1.0，不通过放宽版本范围宣称兼容其他宿主。升级步骤见 README“从 0.1.0 更新”。
- 在宿主设置页配置模型和可选网页搜索提供商。选择可以稳定返回 JSON 的模型。
- 安装包首次解析 npm 依赖需要联网；随后演示与文件生成可离线运行。实时政策搜索和模型提取必须联网。

## 常见操作

1. 打开工作台：对 DSH 说“打开政策寻源工作台”。
2. 选择范围：例如“广东制造业中小企业稳岗补贴”，展开来源、日期和模型设置。
3. 如已知原文网址，按行粘贴。目录扫描只作为没有搜索结果时的后备路径；一个目录抓取失败不会伪装成无政策。
4. 发起任务：查看进度；可以取消。completed 表示本次处理完成，partial 表示部分来源失败，failed 表示未能完成，interrupted 表示上次宿主关闭时中断。
5. 打开“逐字段核对”，查看每字段的摘录、原文链接和待核实项。
6. 导出 XLSX/DOCX/PDF。运行中导出会明确标为阶段快照；需要完整证据时导出 JSON。

## FAQ

**没有模型**：到 DSH 配置提供商，再刷新工作台。独立演示故意不自动寻找环境变量中的密钥。

**搜索服务不可用**：仍可直接处理原文 URL，或者扫描默认目录。任务里会记录网页搜索失败，不描述为已完成全网检索。

**代理使用假 IP DNS**：在该插件 config 设置 `dnsResolver: alidns`，重启插件；默认仍是 system。公共 DoH 返回的地址也必须通过公网检查。不要关闭 HTTPS 验证或允许私网目标。

**园区域名被拒绝**：核实其为目标园区/政务平台后，在 allowedHosts 中添加精确主机名。子域名不是自动放行，需分别配置。

**扫描件、反爬、robots 禁止**：任务保留失败原因；人工访问来源并核验。本版不提供 OCR 或自动浏览器登录。

**无截止日期**：保留“待核实”，有效期不能代替申报日期。原文“长期有效”或多个批次需查看证据，不填一个猜测日期。

**字体差异**：PDF 内嵌字体。DOCX/XLSX 声明 Noto Sans CJK SC；未安装的编辑器会替换字体，如需相同外观可使用包内 OFL 字体。Word/WPS/LibreOffice 的分页可能略有差异。

**数据与清理**：数据为插件目录下 JSON；卸载插件不会删除历史。确认不再需要后可自行备份/删除 `policy-search` 数据目录。应用没有全盘索引，也不会后台周期运行。

## 开发与发行

执行 `npm ci`、`npm run check`、`npm test`。`node scripts/demo-artifacts.js` 生成明确标记的演示交付物；Python 校验器不依赖第三方 Python 包。真实网络冒烟脚本：

```sh
POLICY_DNS_RESOLVER=alidns node scripts/live-fetch.js 'https://官方域名/政策原文'
```

不设置环境变量时使用系统 DNS。该脚本只核实抓取，不调用模型，不生成“AI 实测通过”的结论。

执行 `npm run pack:release` 产生 TGZ、源码 ZIP、SHA-256；发布到私密 GitHub Release 后，下载仍需该仓库访问权限。未经用户要求不上传模型密钥、原始需求 DOCX、搜索历史或真实政策正文快照。
