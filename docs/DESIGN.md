# 设计与需求映射

需求依据：用户提供的《AI政策搜索智能体.docx》。文档中的提交日期是原始背景，不作为本插件执行外部提交或创建自动化的指令。原文的“XSL/Doc”按用户认可的 XLSX/DOCX 实现，并提供 PDF。

| 原始要求 | 实现与验收入口 |
|---|---|
| 全国各级政府、园区、政务平台多源抓取 | DSH `web.search` 搜索候选，支持省/市官网目录；直接政策 URL；非 gov.cn 平台通过 allowedHosts 精确授权；HTML/文字 PDF 解析 |
| 最新政策与自动处理 | 一次发起后自动发现、抓取、模型提取、证据校验和成稿；发布时间排序和日期范围过滤；保留抓取时间，未知日期不猜测 |
| 有效政策识别与分类 | 模型排除非政策原文与不相关资料；提取地区、层级、行业、类型、效力说明；截止日期/有效期作风险提示，最终效力人工复核 |
| 关键字段 | 12 个字段及每字段原文证据，未获原文支持则清空或改用摘录；多个申报批次不合成一个截止日期 |
| 标准化简报 | XLSX、DOCX、PDF，另附可审计 JSON；三格式来自同一结果快照 |
| 图形化界面 | 本机鉴权工作台，主题/筛选/来源/模型、历史任务、进度与取消、证据查看和导出 |
| 功能可运行、不崩溃 | 有界并发、限时、体积上限、有限重试、任务失败/部分完成状态、持久化和重启恢复边界 |
| 程序、源码、使用部署文档 | DSH Bundle TGZ、Node CLI 演示入口、完整源码及 README/部署/验证记录 |

## 结构

`src/index.js` 负责 Cordis 服务绑定、四个工具和两个技能；复用 `ctx.llm` 与 `ctx.web`，不自行管理外部模型密钥。

`engine.js` 管理任务生命周期和精确请求日志；`fetcher.js` 执行允许来源、公网地址、重定向、robots、编码与文件大小校验；`policy.js` 定义证据核验和筛选；`export.js` 将结构化快照制作成办公文件；`server.js` 提供仅本机的带令牌 API；`public/` 是无框架图形工作台。

`skills/policy-office` 集成 MIT 开源办公技能，按目标格式加载。生成不依赖 Python 或 Office；上游验证脚本和格式资料是开发核验工具及模型指导。

## 与参考项目的区别

参考项目是通用中国政策检索 Skill，包含确定性脚本、缓存和 HTML 汇编。本插件独立实现企业扶持字段、DSH 原生扩展、图形任务界面和三种办公格式，并围绕证据、申报期限歧义及来源失败提供可观察状态。没有继承上游的历史缓存覆盖率，也不把有限搜索称为全网穷尽。

## 边界

图形工作台在 DSH 插件进程内按需提供一个本机监听器，随插件卸载关闭；不会改动 DSH 主界面或其他插件。通过对话工具获得链接，因此也适用于不支持某个 Web UI slot 的宿主；远程服务器部署不能把本机链接直接当成公开页面。

正文证据匹配只能证明摘录存在，不能证明模型解释正确。原文中的指令不作为执行指令。没有登录绕过、验证码破解、自动申报、外部发信、定时监控或 npm 公开发布。
